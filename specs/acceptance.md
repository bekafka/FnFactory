# 验收阶梯规范

**适用**：所有 fpk 应用，安装到真机后必须跑一遍。
**继承**：`templates/tests/accept.sh`（把占位符换成应用的值即可）。

用法：`bash tests/accept.sh all`，也可单跑 `endpoints` / `lifecycle` / `ops`。
判定：**任何一条 FAIL 都不算通过**，不许"部分通过先发版"。

---

## 为什么是阶梯而不是一个冒烟脚本

一个包"装上了"和"能用"之间隔着好几层，混在一起出问题就说不清是哪层：
进程活着但端口没开、端口开了但页面 404、页面能开但下载失败、功能正常但重启后数据没了……

所以按依赖顺序分层，**前一层不过就不该看下一层**：

| 阶段 | 验什么 | 典型失败原因 |
|---|---|---|
| 1 状态 | `appcenter-cli status` = running | 生命周期脚本语法错、运行时缺失 |
| 2 端点 | `/healthz`、首页、静态资源、局域网 IP | 只监听 127.0.0.1、`data-share` 挂不上 |
| 3 鉴权 | 负例（无凭据）与正例（带凭据）**都要** | 鉴权根本没生效，或把健康端点也挡了 |
| 4 端到端 | 走一遍真实业务（下载/请求/写入） | 权限、存储路径、外部依赖 |
| 5 生命周期 | stop → 端口释放、无残留进程 → start → 就绪 | 孤儿进程、pid 身份判断、状态文件 |
| 6 运维项 | 目录/文件权限、日志轮转、内存参数、卸载向导 | 规范没落实 |

## 硬性要求

1. **用真机、经网关/局域网 IP 各验一次**（只测 127.0.0.1 会漏掉绑定地址问题）。
2. **端到端要断言产物**（文件存在 + 大小/sha256 + 属主），不能只看"任务创建成功"。
3. **stop 之后必须扫孤儿**：`ss -ltn` 无本应用端口 + `/proc/*/exe` 无本应用进程。
4. **重启后要验数据**（库文件还在、配置还在），这是"保留配置卸载"的前提。
5. 每次跑之前清掉上次的产物（文件名带时间戳，别让上一次的文件冒充这一次的成功）。

## 阶段 6：把规范变成断言

阶段 6 的意义是**让规范可执行**——规范写在文档里会腐化，写成断言才会有人管：

```bash
# 数据目录对其他用户可进入（0755）
[ $(( 0$(stat -c %a "$SAVE") & 0005 )) -ne 0 ]
# 下载/产出文件可读（0644）
[ $(( 0$(stat -c %a "$FILE") & 0004 )) -ne 0 ]
# 权限修正轮询在跑
kill -0 "$(cat $PKGVAR/perm-fix.pid)"
# 内存参数生效
tr '\0' ' ' < /proc/$PID/cmdline | grep -q -- "--max-old-space-size="
# 卸载向导存在且字段名正确
grep -q wizard_uninstall_mode /var/apps/$APPNAME/wizard/uninstall
```

## 不能自动化的部分（写进发布 checklist）

- App Center 里点一下桌面图标，确认能打开；
- 点一次「卸载」→ 选「完全卸载」→ 确认数据真的没了 → 重装；
- 应用设置页改端口后，入口跟着变。
